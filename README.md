# escalator (Work in progress)

Cost-aware escalation routing for a data-analysis agent. A self-hosted small model writes and
executes SQL first; an uncertainty signal decides whether to escalate to a frontier model. This
repo measures what that policy buys and what it costs, against local-only and frontier-only
baselines, on a pinned subset of an expert-corrected benchmark with execution-verified ground
truth.

**The deliverable is the measurement, not the agent.**

> **Status: week 0 of 4.** Every result cell is blank by design. The table was written before the
> code, so that the code has nothing left to decide. No number here is a projection — cells fill
> only from committed artifacts under `results/`.

Both exclusion classes are listed by id in the manifest with their reason. Date-dependent gold
(`now|CURRENT_(DATE|TIME|TIMESTAMP)`) makes EX itself a function of the run date, which would break
the week-4 reproducibility criterion. Gold slower than the sandbox timeout is unreachable by any
agent, so scoring it would measure the sandbox.

`make manifest` executes every gold query against the pinned databases and stores the sha256 of
each canonicalized result set. A gold query that errors or returns ∅ flags a database mismatch
before any spend. That hash is what "pinned by row hash" means, and `eval/tasks.py` verifies every
one on load.

## Method

**Agent loop.** ReAct-style, one model per tier, max 8 model steps with an explicit stop condition.
Four tools — schema inspection, row sampling, SQL execution, answer submission — each validated
against a JSON schema; on validation failure the model gets a typed error and up to 2 retries.
Retries are counted and do not consume the step budget. One JSONL trace line per step:
`{task_id, run_id, step, tier, model, tool, args, result_hash, tokens_in, tokens_out, latency_ms, usd}`.
Everything downstream — metrics, routing simulation, failure taxonomy — reads traces, never live
calls.

**Router.** For task `i`, let `a_i^S, a_i^L ∈ {0,1}` be per-tier correctness, `c_i^S, c_i^L` their
costs, and `s_i ∈ ℝ` a signal computed without ground truth. A policy escalates `E = {i : s_i > τ}`:

```
Acc(τ)  = (1/n) [ Σ_{i∉E} a_i^S + Σ_{i∈E} a_i^L ]
Cost(τ) = (1/n) [ Σ_i c_i^S     + Σ_{i∈E} c_i^L ]
```

`c_i^S` is not zero: it is local GPU seconds at the pinned rate. On the API panel it is zero by
construction and no ratio is quoted there. Per-task gain is `δ_i = a_i^L − a_i^S`. The
**unconstrained oracle** escalates exactly `{i : δ_i = +1}` and is a single point. The **oracle
frontier** is the curve traced by admitting those tasks in increasing `c_i^L` under a sweeping
budget, and is the dashed line on the plot. Both are in-sample. Signal quality reduces to one
number: AUC of `s_i` against `1[δ_i = +1]`.

**Cost simulation.** Both tiers run over the pinned tasks once, in week 2, including the extra
local passes the signals need (k = 3 at T = 0.7; one re-phrased verifier query). From then on every
signal, threshold, oracle variant and knapsack is post-processing over recorded outcomes at zero
marginal token cost. Exact only if per-tier outcomes are deterministic — at T = 0 with fixed seeds
they approximately are. The measured frontier flip rate (Table 7) is the size of that assumption's
error.

**Environment as an MCP server.** The sandbox and its four tools run as an MCP server over stdio;
the agent loop is its only client in the experiment. Any MCP client can query the same databases:

```json
{
  "mcpServers": {
    "escalator": {
      "command": "uv",
      "args": ["run", "--locked", "-m", "escalator.env.server", "--db-root", "data/raw/bird"]
    }
  }
}
```

Sandbox: read-only connection (`file:…?mode=ro&immutable=1`), 5 s statement timeout, 1000-row cap,
`ATTACH` and `PRAGMA` rejected. Four invariants keep the MCP boundary from perturbing the
measurement — canonical tool manifest hashed into the cache key; both tiers calling tools through
the same client, with no provider-side execution; deterministic stateless tools; exactly one
validation site. Each is tested in `tests/test_mcp_invariants.py`.

## Statistical protocol

- n = **\_\_\_**, fixed in advance, stratified, seed pinned, committed before any sweep.
- **All comparisons are paired.** The test is McNemar's on the discordant pairs *of that
  comparison*: `b` = tasks the first policy gets right and the second wrong, `c` = the reverse,
  reported with an exact binomial p-value. These are policy-pair-specific and are **not** the same
  counts as `P(δ = ±1)` in Table 2, which is the tier contrast.
- **Resolution is set by discordance, not by n**: `SE(Δ) = √(b + c − (b−c)²/n) / n`. A routed policy
  agrees with the frontier on every escalated task by construction, so `b + c` is small and the
  paired interval is materially tighter than the ±7pp an independent-sample calculation gives at
  n = 200. The achievable resolution is reported next to Δ rather than assumed in either direction.
- CI on a paired difference of proportions: **Tango's score interval**. Not Wilson — Wilson is a
  single-proportion interval and does not apply to a correlated difference.
- Cost per solved task is a ratio of two random quantities: bootstrap over tasks, 2000 resamples,
  percentile interval. Not propagated analytically.
- **Threshold selection is disclosed.** Two τ are written into `configs/policy.yaml` before the
  sweeps are scored and are the values the claim quotes. The accuracy-maximising τ is also
  reported, labelled in-sample, beside a 5-fold nested-CV estimate that selects τ out-of-fold.
- Every number carries an interval or is explicitly labelled a point estimate.

## Limitations

- **Contamination.** BIRD is public, famous, and likely partly memorized. Unfixable. Named here;
  the hard slice is the uncontaminated counterweight and is never pooled with Table 1.
- **Residual label noise is unmeasured.** Plat-Full is expert-corrected, not proven correct. The
  "correct but scored wrong" row is a lower bound on what remains.
- **Difficulty labels are approximate.** They come from Mini-Dev's uncorrected questions, joined on
  id; Plat-Full rewrote some of those questions. Table 4 inherits that slack.
- **n = 200, one benchmark, one SQL dialect, 11 schemas.** Nothing here generalizes to
  warehouse-scale schemas or to dialects requiring transpilation.
- **Threshold and oracle are in-sample** on this manifest; nested CV mitigates, does not eliminate.
- **Simulation determinism** is assumed at T = 0 and bounded by the measured flip rate, not proven.
- **One frontier model, one provider.** The escalation arithmetic is provider-agnostic; the numbers
  are not.
- **Costs are a dated snapshot** and GPU amortization depends on one pinned rate.
- **The hard slice is authored and reported by the same person.** Rationales are committed so the
  judgement is auditable; it is not an independent benchmark.

## Not in scope

- No UI. No Streamlit, no Chainlit.
- No RAG, no vector store, no embeddings.
- No fine-tuning.
- No provider-side tool execution, including API-hosted MCP connectors. Both tiers call tools
  through the same client, or `δ_i` absorbs harness differences.
- No multi-agent crew. A verifier pass here is a tool call, not an agent.
- No new benchmark. This consumes one.
- No attempt at SOTA. This measures a trade-off; it does not climb a leaderboard.
